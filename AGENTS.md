# AGENTS.md

Рабочий контракт для агентов в репозитории отслеживания подхода судов к порту Владивосток.

Конфигурация 1С EDT `Harbor`, совместимость 8.3.27, язык модулей русский, управляемые формы, `modalityUseMode = DontUse`, `synchronousPlatformExtensionAndAddInCallUseMode = DontUse`. Карта — MapLibre GL JS в HTML-поле тонкого клиента.

Текущий этап и все вводные — `.cursor/plans/этап_1_карта_подхода_судов.plan.md`. В будущем возможна интеграция с цифровым двойником контейнерного терминала D3 (`C:\1c\d3`). Пока это отдельная конфигурация, код D3 не меняется.

## Правила разработки

Для изменения метаданных использовать EDT MCP, а не править xml.
Для соблюдения стандартов разработки используй v8std MCP.
Писать код по SOLID, DRY и KISS:

- **S**ingle Responsibility — один модуль/процедура/функция решает одну задачу.
- **O**pen/Closed — расширять поведение без ломки существующего кода (новые ветки, адаптеры, параметры), а не правкой всех вызовов.
- **L**iskov Substitution — подмена реализации (источник данных, адаптер) не ломает контракт вызывающего.
- **I**nterface Segregation — не тащить лишние параметры и поля «на всякий случай»; контракт ровно под задачу.
- **D**ependency Inversion — зависеть от абстракции (контракт судна, команда viewer), а не от конкретного провайдера AIS.
- **DRY** — не копировать логику; общее вынести в одну процедуру. Дубли констант, маппингов и разбора JSON — ошибка.
- **KISS** — самое простое решение, которое работает; без лишних слоёв, флагов и обобщений «на будущее».

Код:

- Экспортные методы документируются комментарием над методом в формате стандарта: описание, `Параметры:`, `Возвращаемое значение:`. Для структур и соответствий перечислять поля (`* Поле - Тип - описание`).
- Комментарий объясняет «почему», а не «что». Не комментируйте очевидное.
- Подавление проверки EDT (`//@skip-check <id>`) — только точечно над строкой и только когда предупреждение ложное.

## Внешние источники

- Внешние сервисы (провайдеры AIS) вызывает только сервер: регламентное задание или явная команда пользователя. Форма во внешние системы не ходит, а читает последний снимок из регистра.
- Хранится только последний успешный снимок, без истории. Ошибка получения, проверки, преобразования или записи пишется в журнал регистрации и **не меняет** прежний снимок.
- Успешный пустой ответ — это актуальное пустое состояние, он перезаписывает снимок.
- Адаптер провайдера приводит ответ к внутреннему контракту судна (план этапа 1, раздел 5). Viewer знает только контракт. Новый провайдер — это новый адаптер, а не правка viewer.
- Сбой одного источника не отменяет остальные.

Не коммитьте пароли, токены и адреса с учётными данными. В частности, значение константы `ТокенOpenWaters`.

## Инварианты

- BSL: не смешивайте клиент и сервер, не используйте модальные и синхронные вызовы платформы.
- Имена свойств JSON, которые 1С читает в `Структура`, не могут содержать точку или пробел. Ответы внешних провайдеров разбирайте `ПрочитатьJSON(…, Истина)` в `Соответствие`: в них бывают необязательные поля и произвольные ключи (`name:ru`, ключи `attribution`).
- HTML страницы собирается на сервере из макетов заменой плейсхолдеров. Плейсхолдеры уникальные, вида `/*@@ИМЯ@@*/`. JSON, вставляемый в `<script>`, экранируется заменой `</` → `<\/`.
- Обмен 1С ↔ JS — только через мосты `#map-command-bridge` (1С → JS: `data-payload` + `data-seq` → `click()`, запасной `fireEvent` → `data-ack` / `data-error`; только `&НаКлиенте`) и `#map-event-bridge` (JS → 1С: клик по `#event:<тип>`, данные — атрибуты `data-message` / `data-text` узла, без разбора JSON на клиенте; обработка в `КартаПриНажатии`).
- Серверные вызовы формы карты — `&НаСервереБезКонтекста`: в реквизите формы лежит мегабайт HTML, контекстный вызов гонял бы его на каждом такте.
- Библиотека и свой код — в разных `<script>`, первым идёт сборщик ошибок `window.onerror`. Свой код начинает с проверки `typeof maplibregl` и при отказе сообщает `error` в 1С.
- Координаты в контракте, параметрах района и viewer — `[lon, lat]` (RFC 7946). Порядок провайдера (`lat, lon` у Open Waters) — только внутри его адаптера.
- MapLibre GL JS встроен в макет, CDN в рантайме не используется. Версия **1.15.3**: HTML-поле 8.3.27 — V8WebKit уровня Safari 11–12, без ES2020, WebGL2 и `fetch` (диагностика 17.10.2026), а 1.15.3 работает на WebGL1 и ES5 и загружает ресурсы через XHR. MapLibre 5.x требует WebGL2 и ES2020, 6.x — ещё и ES-модули с worker по URL. Возврат на 5.x — только после того, как форма «Диагностика» покажет WebGL2 и ES2020 у клиентов (обновление браузерного движка поля в плане 1С на 8.5.5); `МакетJS` совместим с обеими версиями.
- Свой код viewer (`МакетJS`, `ДиагностикаHTML`) — без синтаксиса новее ES2017: никаких `?.`, `??`, BigInt, полей классов. Новые API браузера — только с проверкой наличия (`ResizeObserver` → запасной `window.resize`).
- Карта и данные — в WGS84 (`EPSG:4326`). Геометрия D3 хранится в `EPSG:32652` и при интеграции пересчитывается при сборке, а не в рантайме.
- Атрибуция OSM / OpenMapTiles, OpenSeaMap и провайдера AIS видна на карте постоянно.
- Права: служебное в формах скрывать по `ПравоДоступа`, не по имени роли. Роль-маркер без прав на объекты проверять через `РольДоступна` (#std737 п. 4.1). Новый объект, который читает карта, добавляйте в права роли `Пользователь`.

## Команды и проверка

- После BSL и метаданных: EDT MCP `get_project_errors`. Ожидаемый остаток — информационные `right-*` о правах корня конфигурации у ролей.
- После правок формы: `validate_form_model` и `get_form_screenshot` с `refresh: true` (подробно — `docs/edt-forms.md`).
- После правок JS/HTML/CSS откройте форму карты в тонком клиенте. Автотестов viewer нет. В комментариях BSL не пишите слово `seen`: EDT читает в нём ключевое слово ссылки «See» и ломает разбор описания.

Дополнительно: `docs/edt-forms.md` — формы через EDT MCP, раскладка, падения конструктора.
