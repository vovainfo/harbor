# Отслеживаемые суда на карте V2

## 1. Цель

Диспетчер отмечает суда, за которыми следит (прежде всего — ожидаемые к подходу), и видит их на карте выделенными среди остальных, а также списком с состоянием: есть ли у судна позиция и насколько она свежая.

Решения пользователя (18.10.2026):

| Вопрос | Решение |
|---|---|
| Чей список | **Общий** для всех пользователей |
| Категории | **Одна** — «Отслеживаемое»; разные категории и цвета — позже |
| Кто ведёт список | **Все** пользователи карты; вопрос прав пока не решаем. Видимость команд по праву не ограничиваем — это осознанное отступление от общего правила AGENTS.md прятать служебное по `ПравоДоступа` |
| Ожидаемое время подхода, уведомления о входе в акваторию | **Отложено** |

Вне этого плана: личные списки, категории и цвета, ожидаемое время подхода, уведомления, разграничение прав, автоматическое заполнение из внешних систем (ЕДС судозаходов). План устроен так, чтобы их можно было добавить без переделки (раздел 8).

Ревью плана — `.cursor/plans/ревью_отслеживаемые_суда_v2.plan.md`, все правки внесены (раздел 12).

## 2. Хранение списка

Справочник **`ОтслеживаемыеСудаV2`** (без иерархии, код не нужен):

| Реквизит | Тип | Назначение |
|---|---|---|
| Наименование | Строка 100 | Название судна (из AIS при добавлении из карточки или вручную) |
| `IMO` | Число 7, неотрицательное | Номер ИМО — постоянный, совпадает с портовыми документами |
| `MMSI` | Число 9, неотрицательное | Идентификатор AIS; есть у всех судов с AIS, может смениться при смене флага |
| `Комментарий` | Строка 500 | Зачем отслеживаем («ожидается 20.10, контейнеры»): ожидаемого времени отдельным полем пока нет |
| `Добавил` | Строка 100 | Имя пользователя |
| `ДатаДобавления` | Дата и время, UTC | |

Почему справочник, а не регистр сведений: у судна может не быть ни IMO (мелкие суда), ни постоянного MMSI, а ключом регистра пришлось бы делать искусственный идентификатор. Справочник даёт ссылку, стандартные формы списка и элемента и пометку удаления без своего кода.

Незаполненный номер в справочнике хранится как **0**, не NULL — все условия ниже это учитывают.

Модуль объекта:

- **`ОбработкаПроверкиЗаполнения`**:
  - заполнен IMO **или** MMSI (хотя бы один ненулевой);
  - IMO — 7 цифр, MMSI — 9 цифр (если ненулевые);
  - дубль — это **другой** (`Ссылка <> &Ссылка`) непомеченный элемент с тем же **ненулевым** IMO или тем же **ненулевым** MMSI. Условие `IMO = &IMO` при нулевом параметре совпало бы со всеми элементами без IMO, а без `Ссылка <> &Ссылка` проверка находила бы сам записываемый элемент.
- **`ПередЗаписью`** — у нового элемента `Добавил = ИмяПользователя()`, `ДатаДобавления = ТекущаяУниверсальнаяДата()`. Правка комментария автора и дату не перезаписывает. На карточке дата показывается местным временем сеанса, как в строке состояния формы карты.

Помеченные на удаление элементы на карту не попадают: и пометка в форме списка, и `Удалить()` из карточки снимают судно с карты. «Не отслеживать» из карточки удаляет элемент непосредственно: список отслеживания — не учётные данные, история не нужна.

## 3. Сопоставление со снимком AIS

Правило одно и живёт в одном месте на каждой стороне — модуль менеджера справочника на сервере и функция `isWatched` во viewer:

1. Если у элемента списка и у судна есть IMO (ненулевой) — сравниваем IMO.
2. Иначе сравниваем MMSI.

Так судно, сменившее MMSI (смена флага), продолжает подсвечиваться по IMO; судно без IMO — по MMSI.

## 4. Контракт и доставка на страницу

### 4.1. Контракт списка

Снимок AIS не меняется; список — отдельный контракт (viewer знает контракт судна и список ключей, но не справочник):

```json
{"version": "9f1c…", "vessels": [{"imo": 9183843, "mmsi": 629009576, "name": "YORIK"}]}
```

- **Канонический текст** — JSON массива `vessels`, собранный `ЗаписьJSON` один раз: ключи элемента по порядку `imo`, `mmsi`, `name`; нулевой номер пишется как `null` (`Неопределено`, как `imo` в снимке); порядок элементов стабильный — запрос с сортировкой по IMO, MMSI, наименованию. Без сортировки хеш менялся бы на каждом такте и `setWatchlist` уходил бы каждые 30 с.
- **`version`** — hex MD5 канонического текста (`ХешированиеДанных`, строка в UTF-8). Хешируется массив, а не объект с самим `version` внутри. У пустого списка тоже есть версия — иначе снятие последнего судна не погасит подсветку.
- Модуль менеджера справочника `СписокДляКарты()` возвращает структуру `Версия`, `Текст` (готовый объект `{"version":…,"vessels":…}`).

### 4.2. Доставка

1. **Открытие формы** — `СобратьHTMLКарты` вставляет `"watchlist": <Текст>` в начальные данные (строка целиком проходит экранирование `</` → `<\/`) и возвращает `ВерсияСписка`. Форма хранит версию в реквизите `ВерсияСписка`, как `ДатаСнимка`.
2. **Такт опроса (30 с)** — `ОбновлениеКарты(ИзвестнаяДата, ИзвестнаяВерсияСписка)` всегда возвращает `ДатаПолучения`, `ВерсияСписка`, `Состояние` и **массив готовых строк команд** `Команды`: `updateVessels` — когда снимок новее, `{"op":"setWatchlist","watchlist":<Текст>}` — когда версия отличается. Строки сервер собирает конкатенацией, клиент 1С их не разбирает и не склеивает: страница делает один `JSON.parse` на клик, каждая строка — отдельный вызов моста.
3. **Карточка судна** — после «Отслеживать» / «Не отслеживать» серверный вызов карточки возвращает и текст команды `setWatchlist`, и её `Версия`; карточка шлёт `Оповестить("ОтслеживаемыеСудаV2Изменены", Новый Структура("ТекстКоманды, Версия", …))`. Форма карты в `ОбработкаОповещения` ставит команду в очередь и запоминает версию — следующий такт список не повторяет. Своего серверного вызова у формы карты нет. Изменения из формы списка доходят на ближайшем такте.

Обновить сигнатуру и разбор результата во **всех** текущих вызовах: обёртка формы `ОбновлениеКарты`, такт `ОбновитьКартуПоТакту`, `РезультатКомандыСнимка` (кнопки «Получить данные сейчас», «Загрузить снимок из файла», «Загрузить из макета»), `ПрименитьОбновление`.

### 4.3. Очередь команд

Сейчас `ОтправитьКомандуКарте(…, ОтложитьПриОтказе = Истина)` держит одну строку `ОжидающаяКомандаКарты` и записывает новую поверх прежней. Так отправляются `updateVessels` и `startMap` (`ЗавершитьПереносКеша`); очередь только в такте не помогла бы — `startMap` затёр бы стоящий `setWatchlist`, и наоборот.

- Очередь (массив строк) ведёт **`ОтправитьКомандуКарте`** для всех отложенных команд: `updateVessels`, `setWatchlist`, `startMap`. Пакеты кеша (`ОтложитьПриОтказе = Ложь`) в очередь не ставятся, как и сейчас.
- Новая команда встаёт в конец; отправка идёт с головы по одной.
- Мост не готов (`ОтправитьКоманду` вернула `Ложь`) — хвост остаётся, начиная с этой команды, до следующего такта.
- Исключение (страница вернула `data-error`) — снимается **только эта** команда, текст — в строку состояния, следующие отправляются.
- Такт, как и сейчас, сначала отправляет хвост, потом ставит команды обновления.

## 5. Отображение на карте (`МакетJS`, `МакетHTML`, `МакетCSS`)

Цвет единственной категории — **`#00E5FF`** (константа viewer): его нет ни в группах судов (`GROUPS`, оранжевый буксиров `#EF6C00` с прежним `#ff6d00` сливался), ни в `SEAMARK_COLOURS`, ни у выделения `#ffd600`.

| Элемент | Как |
|---|---|
| Признак | `rebuildVesselData` ставит `watched` по правилу раздела 3 **и точкам, и корпусам**: фильтр и цвет корпуса читают свойства корпуса |
| Кольцо | Слой `vessel-watched-ring` (circle, без заливки, обводка 2, радиус 18 — больше жёлтого круга выделения 15) под значками. В `clickableLayers` не нужен: значок и корпус над ним уже открывают popup |
| Значок | `symbol-sort-key`: 1 у отслеживаемых, 0 у остальных; `symbol-z-order` не трогаем — `auto` сортирует по ключу. Значок отслеживаемого крупнее (`icon-size` ≈ 1,3) |
| z14 и крупнее | Значок судна с корпусом скрыт фильтром `vessel-icons-hull-zoom` (`hasHull != true`) — там отслеживаемое показывают кольцо и контур корпуса; значок поверх корпуса отдельным слоем не возвращаем |
| Корпус | Выражение `line-color` у `vessel-hulls-line`: цвет категории для `watched`, иначе `#263238`. Жёлтый `vessel-hulls-selected` остаётся сверху |
| Подпись | Слой `vessel-labels-watched` без `minzoom` (обычные — с z12), шрифт **`Noto Sans Bold`** (стек скачан загрузчиком из стилей во всех шести диапазонах), кегль 12, ореол цвета категории; видимость — флажок «Названия судов» через `applyLayerState`, как у `vessel-labels` |
| Флажок «Только отслеживаемые» | `ui.watchedOnly`, по умолчанию выключен. Условие `watched == true` добавляется **в `applyLayerState`** к фильтру возраста (и к `hasHull` у `vessel-icons-hull-zoom`) на слоях `vessel-icons`, `vessel-icons-hull-zoom`, `vessel-labels`, `vessel-hulls-fill`, `vessel-hulls-line`, `vessel-selected`, `vessel-hulls-selected`. Новые id — в `OWN_LAYERS`. Иначе смена подложки соберёт слои заново без этого фильтра |
| `setWatchlist` | До `startMap` только запоминает список и вызывает `rebuildVesselData` (источников ещё нет — так же ведёт себя `updateVessels`); такт во время переноса набора такую команду прислать может. После создания карты — `setData` точек и корпусов, перестройка панели, `refreshPopup` |
| Popup | Строка «Отслеживается». Комментария в popup нет: он только в карточке и в контракт списка не входит |
| Легенда | Строка «Отслеживаемое» с кольцом |
| Панель «Отслеживаемые суда» | Под легендой, с `max-height` и прокруткой (легенда стоит на `top: 110px`; длинный список иначе закроет карту). Заголовок «на карте N из M», N — суда со статусом «на карте» и «позиция старше 1 ч». Строка — название, IMO/MMSI, статус: **на карте** · **позиция старше 1 ч** (`ageMin > 60` от `snapshot.receivedAt`, та же шкала, что легенда; устаревший снимок целиком уже отмечает жёлтая плашка) · **нет в снимке**. Щелчок по строке с позицией — `flyTo` к судну и popup. Панель сворачивается; пустой список — панель скрыта |

Всё, что приходит из внешней сети или от пользователя (название, комментарий), выводится через `textContent`. Синтаксис — не новее ES2017.

## 6. Сервер, карточка судна и форма списка

### 6.1. Модуль менеджера справочника `ОтслеживаемыеСудаV2`

API — в модуле менеджера: у логики один хозяин, отдельный общий модуль не нужен (проверки и `ПередЗаписью` — в модуле объекта).

| Метод | Что делает | Возвращает |
|---|---|---|
| `СписокДляКарты()` | Непомеченные элементы, сортировка по IMO, MMSI, наименованию; канонический текст и версия (раздел 4.1) | `Версия`, `Текст` |
| `Отслеживается(MMSI, IMO)` | Ищет непомеченный элемент по правилу раздела 3 | `Найден`, `Комментарий`, `Добавил`, `ДатаДобавления` (UTC) |
| `Отслеживать(MMSI, IMO, Наименование)` | Нашёл элемент по правилу раздела 3 — обновляет наименование и пустой второй номер, новый не создаёт; не нашёл — создаёт. Иначе повтор из карточки упрётся в проверку дубля, а элемент «только IMO» и судно с тем же IMO и новым MMSI дадут вторую строку панели | Структура `Отслеживается` + `ТекстКоманды`, `Версия` |
| `НеОтслеживать(MMSI, IMO)` | Удаляет **все** непомеченные элементы, которые правило сопоставляет с этой парой (элемент «только IMO» и элемент «только MMSI» на одно судно иначе оставят подсветку) | То же |

`IMO` может быть пустым (`Неопределено` или 0) — тогда сопоставление только по MMSI.

### 6.2. Карточка судна

- Команда «Отслеживать» / «Не отслеживать» и строка «Отслеживается с … (добавил …), комментарий …».
- Заголовок команды и строку считает **`ЗаполнитьСведения`** — её вызывают и `ПриСозданииНаСервере`, и `ПоказатьСудно` (повторное «Подробнее» форму заново не создаёт). Ранний выход «нет в снимке» тоже обновляет команду: MMSI формы уже заполнен, отслеживать и снимать можно по нему без IMO.
- После команды — оповещение карты структурой `ТекстКоманды` + `Версия` (раздел 4.2).

### 6.3. Форма карты

- Команда «Отслеживаемые суда» открывает стандартную форму списка справочника (ручной ввод судна, которого ещё нет в AIS; правка комментария; пометка удаления).
- Обработчик **`ОбработкаОповещения`** привязан к событию формы `NotificationProcessing` (без привязки платформа процедуру не вызывает).
- Права: роли `Пользователь` (`setForNewObjects = false`) явно — чтение, добавление, изменение, удаление и интерактивные права на справочник; справочник — в подсистему `ПодходСудов`.

## 7. Порядок работ

1. **metadata** — справочник, модуль объекта, подсистема, права.
2. **server** — модуль менеджера справочника (раздел 6.1); модуль менеджера `КартаПодходаСудовV2`: `watchlist` в начальных данных, `ВерсияСписка`, `ОбновлениеКарты(ИзвестнаяДата, ИзвестнаяВерсияСписка)` с массивом `Команды`; все вызовы — раздел 4.2.
3. **polling** — очередь в `ОтправитьКомандуКарте` (раздел 4.3), реквизит `ВерсияСписка`, `ОбработкаОповещения`.
4. **viewer** — раздел 5.
5. **card** и **list-form** — разделы 6.2, 6.3.
6. **docs** — AGENTS.md: строка «куда менять» (менеджер справочника), контракт списка, команда `setWatchlist` и очередь команд в инвариантах моста.
7. **check** — раздел 9.

## 8. Расширения позже (без переделки)

- **Категории и цвета** — справочник категорий с цветом, реквизит `Категория`; в контракт элемента добавится `category`, viewer возьмёт цвет из списка категорий в том же контракте.
- **Ожидаемое время подхода** — реквизит и поле `eta` в контракте; панель сортирует по нему.
- **Уведомление о входе в акваторию** — сервер (регламент после записи снимка) сравнивает снимок со списком; viewer не меняется.
- **Заполнение из внешней системы** — загрузка пишет в тот же справочник (IMO из заявки на заход).
- **Права** — роль «Диспетчер» на изменение справочника, видимость команд по `ПравоДоступа`.

## 9. Критерии приёмки

- Судно из popup → «Подробнее» → «Отслеживать»: в течение секунды на карте у него кольцо, значок поверх остальных, постоянная подпись; оно в панели со статусом «на карте». «Не отслеживать» снимает подсветку так же быстро. Повторное «Отслеживать» не создаёт второй элемент.
- Карточка, открытая повторным «Подробнее» по другому судну, показывает состояние отслеживания этого судна; для судна «нет в снимке» команда тоже работает.
- Судно, добавленное в форме списка (в том числе по IMO без MMSI или судно не из снимка), появляется в панели не позже чем через 30 с; без позиции — «нет в снимке». Правка комментария элемента в форме не считается дублем и не меняет автора и дату.
- Сопоставление: элемент с IMO подсвечивает судно с тем же IMO при другом MMSI; элемент только с MMSI — по MMSI.
- Дубль по ненулевому IMO или MMSI и элемент без обоих номеров не записываются, сообщение понятное.
- «Только отслеживаемые» скрывает остальные суда и корпуса и переживает смену подложки.
- Неизменный список не отправляется на каждом такте (версия стабильна); удаление последнего элемента гасит подсветку.
- Команды не теряются: `setWatchlist`, пришедший во время переноса набора, применяется после `startMap`.
- Список виден всем пользователям (общий); после открытия формы к серверу по-прежнему обращаются только такт опроса и карточка судна.
- `get_project_errors` без ошибок, формы проходят `validate_form_model`; эмуляция в Edge: список в начальных данных, `setWatchlist` по смене версии и до `startMap`, панель, фильтр, переход к судну, без внешних запросов.

## 10. Риски

| Риск | Что делаем |
|---|---|
| У судна в AIS нет IMO, а в списке только IMO | Панель покажет «нет в снимке»; в карточке можно отслеживать по MMSI — номер берётся из снимка, `Отслеживать` дополнит элемент вторым номером |
| Смена MMSI у судна без IMO | Подсветка пропадёт; в панели — «нет в снимке», пользователь обновит MMSI в форме списка |
| Ручной ввод двух строк «только IMO» и «только MMSI» на одно судно | Проверка дубля их не связывает (для этого нужен снимок AIS в проверке заполнения); две строки панели на одно судно. Оставляем; карточка при «Отслеживать» такие строки не плодит, «Не отслеживать» снимает обе |
| Длинный список перегружает панель | `max-height` и прокрутка; при необходимости — сортировка «сначала на карте» |
| Чтение справочника на каждом такте | Десятки строк, один запрос; при росте — версия по `ВерсияДанных` или регистру-счётчику. Ошибку чтения списка отдельно не ловим: права на чтение у роли есть |

## 13. Ход реализации (18.10.2026)

Сделано всё, кроме приёмки в тонком клиенте:

- Справочник `ОтслеживаемыеСудаV2` (без кода; из полей ввода по строке `Код` убран в `.mdo` — EDT MCP это свойство не адресует, а без правки обновление базы падает), модули объекта и менеджера, подсистема, права роли `Пользователь`.
- Отличие от раздела 6.1: `Отслеживать` / `НеОтслеживать` возвращают только состояние (`см. Отслеживается`), а текст команды и версию для оповещения отдаёт `Обработки.КартаПодходаСудовV2.КомандаСпискаОтслеживаемых()` — строку команды viewer собирает модуль обработки, а не справочник. - Очередь команд в `ОтправитьКомандуКарте`, массив `Команды` в такте, `ВерсияСписка` во всех вызовах, `ОбработкаОповещения` привязана к событию формы. Команда формы карты «Отслеживаемые суда» открывает стандартную форму списка.
- Карточка судна: команда «Отслеживать» / «Не отслеживать» и строка отслеживания (поле под сведениями).

- `get_project_errors` без ошибок, формы проходят `validate_form_model`, база обновлена.
- Эмуляция в Edge: `setWatchlist` до `startMap` применяется после создания карты; судно найдено по IMO при другом MMSI; панель «на карте 1 из 2» и «нет в снимке»; щелчок по строке — переход и popup с «Отслеживается»; «Только отслеживаемые» оставляет одно судно и переживает смену подложки; пустой список гасит кольцо, подпись и панель; внешних запросов нет.
