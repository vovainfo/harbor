# Управляемые формы через EDT MCP: раскладка и ловушки

Форму, собранную через `create_metadata` / `modify_metadata`, EDT заполняет значениями по умолчанию, которые отличаются от значений конструктора. Ниже — то, что уже ломалось (опыт проекта D3, `C:\1c\d3\docs\edt-forms.md`), и как это исправить. Когда в Harbor появятся удачные формы, укажите их здесь как эталоны.

## Порядок работы

1. Создавайте форму и её элементы через EDT MCP, XML формы руками не правьте.
2. После правок запускайте `validate_form_model`: он ловит битые пути к данным, команды и обработчики.
3. Проверяйте раскладку через `get_form_screenshot` с `refresh: true`. Для другой страницы передайте `showElement` с элементом на ней. Скриншот покажет то, что `validate_form_model` и `get_project_errors` не видят.
4. Если форма отрисовалась криво, сравните её свойства с эталоном (`get_metadata_details`, `assignable: true`) и найдите отличие.

## Обязательно для каждой новой формы

- **`autoTitle = false`** — сразу при создании формы. Иначе платформа дописывает к заголовку синоним обработки. Заголовок задаётся в `ПриСозданииНаСервере`.

## Проблемы и исправления

| Симптом | Причина | Исправление |
|---|---|---|
| Конструктор EDT не открывает форму, потом не открывается ни одна новая форма | Поле с `listChoiceMode=true` или `dropListButton=true` при пустом списке выбора в метаданных. Нативный рендер EDT падает с делением на ноль | В метаданных оба свойства `false`. Список и режим задавайте в `ПриСозданииНаСервере`: `СписокВыбора.Добавить`, `РежимВыбораИзСписка`, `КнопкаВыпадающегоСписка`, `РедактированиеТекста` |
| Конструктор не открывает форму, а поле диаграммы выглядит как поле ввода | Поле для реквизита `Chart` создаётся с типом `InputField` | `type = ChartField`, затем `width` и `height` больше нуля (валидатор: «The value must be greater than zero») |
| Страниц не видно, показана только первая | У `Pages` не задан `pagesRepresentation`, поэтому вкладки скрыты | `pagesRepresentation = TabsOnTop` |
| Вкладки без подписей | У `Page` по умолчанию `showTitle=false` | У каждой страницы: `showTitle = true`, `group = Vertical` |
| Страницы, таблица или поле HTML не на всю ширину | Не задано растяжение | `horizontalStretch` / `verticalStretch` у `Pages`, у каждой `Page`, у таблицы и у поля HTML-документа |
| Горизонтальная шапка над страницами или таблицей «разъезжается»: первое поле слева, остальные справа, страницы ужаты до ширины первой колонки | 1С выравнивает элементы шапки по общей сетке со следующим элементом | У группы шапки `united = true`. Не помогают ни `throughAlign = DontUse`, ни растяжение, ни `autoMaxWidth=false` у таблицы |
| Таблица только для просмотра, а в её панели «Добавить» и «Переместить» | При создании `changeRowSet` и `changeRowOrder` равны `true` | Оба `false` и `readOnly = true` |
| Рядом диаграмма и таблица, у таблицы обрезаны колонки | Фиксированная `width` таблицы меньше суммы колонок | Диаграмме растяжение, таблице фиксированная `width` по колонкам (для 4 колонок около 42) |
| Колонки таблицы не сужаются, сколько ни уменьшай их `width` | Колонки с `autoMaxWidth=true` делят ширину таблицы между собой. Последняя колонка забирает остаток. Колонку нельзя сделать уже текста её заголовка | У колонок `autoMaxWidth=false` и `width` (1 единица ≈ 10 px). У таблицы `width` = сумма колонок + 3–4 на рамку и прокрутку |
| Кнопки формы не видны | Командная панель формы может создаться скрытой | `visible = true` у `...Group.ФормаКоманднаяПанель` |
| Ошибка в рантайме «Поле объекта не обнаружено» на значении перечисления | Имя значения платформенного перечисления угадано (`РасположениеЛегендыДиаграммы.Снизу` вместо `Низ`) | Сверять через `get_platform_documentation` |

## Если конструктор EDT не открывает форму

- Журнал EDT: `<каталог рабочей области EDT>\.metadata\.log`. Признаки падения нативного рендера:
  - `UnsatisfiedLinkError ... getActionListContent` или `FormNativeVisualizer.render`;
  - NPE `"items" is null`;
  - `CancellationException` в `FormNativeVisualizerLoader`.
- Дампы падений: `%LOCALAPPDATA%\1C\1cedtstart\installations\1C_EDT <версия>\1cedt\hs_err_pid*.log`. В `Command Line` должен быть `FormNativeVisualizerLoader`, в заголовке — тип сбоя, например `EXCEPTION_INT_DIVIDE_BY_ZERO`.
- После такого падения процесс рендера не поднимается сам. Пока EDT не перезапущен, не открывается ни одна новая форма, и скриншоты с проверками в это время ничего не доказывают. При старте EDT заново открывает все редакторы, поэтому перед перезапуском закройте редактор проблемной формы.
- Чтобы найти виновника, не перебирая вслепую (каждая неудачная попытка стоит перезапуска EDT), соберите пары «тип элемента / свойство / значение» проблемной формы и вычтите пары всех остальных `src/**/Form.form`. Оставшиеся уникальные свойства — первые подозреваемые.
